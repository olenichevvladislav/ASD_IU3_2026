## Задача 12. Пара с заданной суммой (Сложность: средняя)

**Условие:**
Вход: массив из n целых чисел и число s.
Выход: индексы i < j, для которых a[i] + a[j] == s. Если пар несколько — вывести пару с наименьшим i, при равенстве — с наименьшим j. Если пары нет — вывести "-1 -1".

### 1. Описание идеи решения и обоснование выбора структуры данных
Для поиска пары используется `HashMap`. Выбор этой структуры обусловлен необходимостью быстрого поиска (за O(1)) числа, которое в сумме с текущим дает `s`. Мы проходим по массиву, запоминая элементы и их индексы. Это позволяет избежать вложенных циклов и снизить сложность с O(n^2) до O(n). При этом мы сохраняем первые и последние индексы, чтобы найти пару с наименьшим первым индексом.

### 2. Анализ асимптотики
**Временная сложность:**
- Первый проход по массиву (заполнение `HashMap`) занимает `n` итераций.
- Второй проход (поиск пары) также занимает `n` итераций.
- Внутри цикла операции с `HashMap` в среднем занимают O(1).
- **Итоговое время:** O(n).

**Пространственная сложность:**
- В худшем случае мы сохраним в `HashMap` индексы всех элементов массива.
- **Итоговая память:** O(n) для хранения словаря.

### 3. Примеры ручных тестов и объяснение, почему они важны
Для проверки алгоритма было написано 10 Unit-тестов (JUnit 5).
1. **shouldReturnExamplePair:** массив `[2, 7, 11, 15, 4]`, сумма `9`. Проверяет нахождение пары в начале массива.
2. **shouldReturnNoPairWhenSumUnreachable:** массив `[1, 2, 3, 4]`, сумма `100`. Проверяет возврат `[-1, -1]`, если пары нет.
3. **shouldReturnNoPairForEmptyArray:** пустой массив. Проверяет, что программа не падает с ошибкой.
4. **shouldReturnNoPairForSingleElement:** массив `[5]`, сумма `5`. Проверяет, что элемент не используется дважды.
5. **shouldHandleNegativeNumbers:** массив `[-5, 2, -1, 4]`, сумма `-3`. Проверяет работу с отрицательными числами.
6. **shouldChooseSmallestRightIndexWhenDuplicatesExist:** массив `[2, 1, 2, 3, 4]`, сумма `4`. Проверяет выбор пары с наименьшими индексами (0, 2) при наличии дубликатов.
7. **shouldChooseSmallestLeftIndexWhenSeveralPairsExist:** массив `[1, 2, 3, 4, 4]`, сумма `5`. Проверяет приоритет наименьшего первого индекса.
8. **shouldNotUseSameElementTwice:** массив `[5, 5, 5, 5]`, сумма `10`. Проверяет, что берутся два разных элемента (0, 1).
9. **shouldFindPairAtTail:** массив `[1, 2, 3, 4, 96]`, сумма `100`. Проверяет нахождение пары в конце массива.
10. **shouldHandleIntegerOverflowInSum:** массив `[MAX_VALUE, MAX_VALUE]`. Проверяет отсутствие переполнения типа `int` при сложении.

## Задача 18. Сортировка только чётных (Сложность: средняя)

**Условие:**
Вход: массив из (n) целых чисел.
Выход: тот же массив, в котором все чётные элементы отсортированы по невозрастанию, а нечётные остались на своих местах.

### 1. Описание идеи решения и обоснование выбора структуры данных
Алгоритм собирает все чётные числа в отдельный массив `evens`, сортирует его с помощью быстрой сортировки (QuickSort) по невозрастанию и возвращает на исходные позиции. Использование QuickSort выбрано из-за его средней сложности O(n log n), что эффективнее пузырьковой сортировки. Дополнительный массив нужен для того, чтобы не нарушать порядок нечётных чисел.

### 2. Анализ асимптотики
**Временная сложность:**
1. **Сбор чётных:** O(n).
2. **Сортировка:** Пусть `k` — количество чётных чисел. QuickSort в среднем работает за O(k log k).
3. **Возврат на места:** O(n).
**Итоговая сложность:** O(n) + O(k log k) + O(n). В худшем случае (k = n) — **O(n log n)**.

**Пространственная сложность:**
1. **Массив `evens`:** O(k) памяти.
2. **Стек рекурсии:** O(log k) памяти в среднем.
**Итоговая память:** **O(k)**.

### 3. Примеры ручных тестов и объяснение, почему они важны
Написано 4 Unit-теста (JUnit 5).
1. **shouldSortMixedNumbers:** `[4, 1, 8, 3, 2]`. Проверяет, что чётные сортируются, а нечётные остаются на своих местах.
2. **shouldSortOnlyEvenNumbers:** `[2, 4, 6, 8]`. Проверяет сортировку массива, состоящего только из чётных чисел.
3. **shouldLeaveArrayUnchangedWhenOnlyOdd:** `[1, 3, 5, 7]`. Проверяет граничный случай, когда сортировать нечего.
4. **shouldHandleEmptyArray:** пустой массив. Проверяет, что алгоритм не выбрасывает исключений.

## Задача 47. Поворот массива на 90 градусов (Сложность: средняя)

**Условие:**
Вход: двумерный массив (n x m).
Выход: массив (m x n), полученный поворотом на 90 градусов по часовой стрелке.

### 1. Описание идеи решения и обоснование выбора структуры данных
Так как при повороте размеры матрицы меняются (с n x m на m x n), используется создание нового двумерного массива. Каждый элемент `matrix[i][j]` переносится в новую позицию `result[j][n - 1 - i]`. Новый массив выделяется, потому что поворот невозможно сделать «на месте» без сложных временных перестановок.

### 2. Анализ асимптотики
**Временная сложность:**
- Два вложенных цикла проходят по всем `n * m` элементам.
- **Итоговое время:** **O(n * m)**.

**Пространственная сложность:**
- Создается новый двумерный массив размером `m x n`.
- **Итоговая память:** **O(n * m)**.

### 3. Примеры ручных тестов и объяснение, почему они важны
Написано 4 Unit-теста (JUnit 5).
1. **shouldRotateSquareMatrix:** матрица 2x2. Проверка базового поворота.
2. **shouldRotateRectangularMatrix:** матрица 2x3. Проверка смены размерности (из 2x3 получается 3x2).
3. **shouldRotateSingleRow:** матрица 1x3. Проверка граничного случая с одной строкой.
4. **shouldHandleEmptyMatrix:** пустая матрица. Проверка обработки отсутствия данных.

## Задача 48. Транспонирование матрицы (Сложность: средняя)

**Условие:**
Вход: квадратная матрица (n x n).
Выход: транспонированная матрица. Требование: на месте (in-place), без создания нового массива.

### 1. Описание идеи решения и обоснование выбора структуры данных
Транспонирование выполняется на месте (in-place) в исходном двумерном массиве. Мы проходим только по элементам выше главной диагонали и меняем их местами с симметричными элементами ниже диагонали. Выбор такого подхода обусловлен жестким требованием задачи: не выделять память под новую матрицу (O(1) по памяти).

### 2. Анализ асимптотики
**Временная сложность:**
- Сумма итераций — арифметическая прогрессия: `n * (n - 1) / 2`, как сумма чисел от 1 (самая нижняя строчка) до n(верхняя строчка).
- **Итоговое время:** **O(n^2)**.

**Пространственная сложность:**
- Новые массивы не создаются, используется одна переменная для обмена.
- **Итоговая память:** **O(1)**.

### 3. Примеры ручных тестов и объяснение, почему они важны
Написано 4 Unit-теста (JUnit 5).
1. **shouldTranspose2x2Matrix:** проверка базового обмена элементов.
2. **shouldTranspose3x3Matrix:** проверка обхода верхнего треугольника без двойной перестановки.
3. **shouldHandle1x1Matrix:** проверка граничного случая, когда обменов не требуется.
4. **shouldHandleEmptyMatrix:** проверка защиты от ошибок при пустом массиве.

## Задача 58. Заполнение матрицы змейкой (Сложность: средняя)

**Условие:**
Вход: числа (n) и (m).
Выход: матрица (n x m), заполненная числами от 1 до (n x m) змейкой по строкам.

### 1. Описание идеи решения и обоснование выбора структуры данных
Создается обычный двумерный массив. Заполнение происходит построчно: в четных строках счетчик идет слева направо, в нечетных — справа налево. Использование массива — единственный способ сохранить результат, так как нам нужно вернуть заполненную матрицу.

### 2. Анализ асимптотики
**Временная сложность:**
- Внешний цикл выполняется `n` раз, внутренний — `m` раз.
- **Итоговое время:** **O(n * m)**.

**Пространственная сложность:**
- Создается матрица размером `n x m`.
- **Итоговая память:** **O(n * m)**.

### 3. Примеры ручных тестов и объяснение, почему они важны
Написано 3 Unit-теста (JUnit 5).
1. **shouldFillSquareMatrixWithSnake:** проверка заполнения квадратной матрицы (2x2).
2. **shouldFillRectangularMatrixWithSnake:** проверка заполнения прямоугольной матрицы (2x3).
3. **shouldFillSingleRowWithSnake:** проверка граничного случая с одной строкой (1x3).

## Задача 59. Определитель матрицы 3x3 (Сложность: средняя)

**Условие:**
Вход: матрица (3 x 3) из целых чисел.
Выход: определитель матрицы.

### 1. Описание идеи решения и обоснование выбора структуры данных
Используется стандартная математическая формула (правило Саррюса). Массив передается в метод, и мы обращаемся к элементам по индексам. Дополнительные структуры данных не требуются, так как вычисление происходит по готовой формуле.

### 2. Анализ асимптотики
**Временная сложность:**
- Размер матрицы фиксирован (3x3), формула содержит константное число операций.
- **Итоговое время:** **O(1)**.

**Пространственная сложность:**
- Новые массивы не создаются.
- **Итоговая память:** **O(1)**.

### 3. Примеры ручных тестов и объяснение, почему они важны
Написано 4 Unit-теста (JUnit 5).
1. **shouldCalculateDeterminantForIdentityMatrix:** проверка правильности знаков (определитель единичной матрицы = 1).
2. **shouldReturnZeroForNullMatrix:** проверка защиты от `NullPointerException` (возвращает 0).
3. **shouldCalculateDeterminantForRandomMatrix:** проверка на произвольной матрице (определитель = 41).
4. **shouldReturnZeroForEmptyMatrix:** проверка обработки пустого массива (возвращает 0).
